#### Отчет и конспект: Развертывание трехзвенного стека в Docker Compose ####

1. **Архитектура проекта и назначение компонентов**

	Построен классический трехзвенный production-like стек: Proxy-App-Database
		==nginx(Фронтенд/Reverse Proxy)==
		Единственный публичный вход в систему. Принимает HTTP-трафик снаружи и передает его на внутренний бэкенд. Защищает приложение от прямого доступа.
		==web(Бэкенд на Python Flask)==
		Слушает порт 5000 внутри Docker-сети. Принимает от Nginx, инкрементирует значение ключа в Redis и возвращает HTML со счетчиком.
		==redis(База данных)==
		Хранит счетчик просмотров. Порт наружу не выставлен. Данные сбрасываются на диск через именованный том.
=================================================================
2.  **Разбор файлов конфигурации**
		**nginx/nginx.conf**
		
			events {}
			
			http {
			    server {
			        listen 80;
			
			        location / {
			            proxy_pass http://web:5000;
			            proxy_set_header Host $host;
			            proxy_set_header X-Real-IP $remote_addr;
			        }
			    }
			}

	`events {}` - обязательная секция ядра Nginx(управление потоками соединений). Без нее Nginx падает на старте.
	`listen 80` - Nginx внутри своего контейнера слушает порт 80.
	`proxy_pass http://web:5000;` - Пересылка запроса. Важно: не айпи адрес, а системное имя сервиса web. Docker сам отрезолвит его IP через внутренний DNS.
	`proxy_set_header X-Real-IP $remote_addr;` - передает реальный айпи адрес клиента бэкенду(иначе Flask думал бы, что все запросы идут от самого Nginx).

	**docker-compose.yml**

		version: '3.8'

		services:
		  # 1. Бэкенд
		  web:
		    build:
		      context: ./app
		      network: host  # Обход файрвола хоста при сборке (pip install)
		    environment:
		      - REDIS_HOST=redis
		    depends_on:
		      - redis
		    networks:
		      - lab-network
		
		  # 2. База данных
		  redis:
		    image: redis:alpine
		    volumes:
		      - redis_data:/data
		    networks:
		      - lab-network
		
		  # 3. Реверс-прокси
		  nginx:
		    image: nginx:alpine
		    ports:
		      - "8888:80"  # 8888 на хосте -> 80 внутри Nginx
		    volumes:
		      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
		    depends_on:
		      - web
		    networks:
		      - lab-network
		
		volumes:
		  redis_data:
		
		networks:
		  lab-network:
		    driver: bridge

3. **Грабли, ошибки и выводы (Lessons Learned)**
		**==Проблема 1==: Зависание pip install во время docker build**
		- Симптом: При сборке контейнера web установка зависимостей из requirements.txt падала по тайм-ауту сети.
		- Причина: Локальный файрвол Linux(UFW/iptables) блокировал транзитный трафик FORWARD из стандартной изолированной bridge-сети Docker в интернет.
		- Решение: Директива `network: host` внутри блока `build:`. На этапе сборки контейнер использовал сетевой стек хоста напрямую, обойдя запреты виртуального моста.
		**==Проблема 2==: Ошибка валидации Compose (`additional properties 'network' not allowed`)**
		- Симптом: Compose ругался на блок сборки.
		- Причина: Опечатка в множественном числе (`networks` вместо `network`). В блоке `build:` параметр сети пишется строго в единственном числе: `network: host`.
		**==Проблема 3==: Синтаксис списков в Yaml**
		- Симптом: Ошибки парсинга при использовании тире `-`.
		- Правило: YAML не переносит значения списков на новую строку без строго отступа. Значение пишется либо сразу через пробел:
			**YAML** 
			`environment:
			  `- REDIS_HOST=redis
		либо со строгим сдвигом в 2 пробела. И никаких символов табуляции (`\t`) - только пробелы.
		==**Проблема** **4**==: Конфликт внешнего порта ==8080==
		- Симптом: Порт ==8080== уже был занят другим процессом на хост-машине.
		- Решение: Изменил маппинг в блоке `ports:` на `8888:80` . Внутри контейнера Nginx продолжает работать на порту 80, а наружу отдает на свободный порт 8888.

4. **Памятка по ключевым концепциям**

|         Концепция          |                                                                           Как работает на моем стеке                                                                           |
| :------------------------: | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------: |
|  Service Discovery (DNS)   |               Docker поднимает внутренний DNS-сервер (`127.0.0.11`). Благодаря этому Nginx стучится в `web:5000`, а Flask подключается к Redis по имени `redis`.               |
|      Сетевая изоляция      | Только у сервиса `nginx` есть секция `ports`. Flask и Redis физически недоступны с хоста по портам `5000` и `6379`. Доступ к ним закрыт внутри виртуальной сети `lab-network`. |
| Named Volume(`redis_data`) |    Контейнеры эфемерны (stateless). Чтобы данные базы не исчезали после перезапуска или пересборки контейнеров, директория базы смонтирована в постоянное хранилище хоста.     |
|  Ready-Only Mount (`:ro`)  |       Конфиг Nginx смонтирован с флагом `:ro` (`./nginx/nginx.conf:/etc/nginx/nginx.conf:ro`). Контейнер не имеет права изменить файл на хосте, даже если будет взломан.       |
5. **Шпаргалка по командам управления стеком**
	==Собрать образы и запустить весь стек в фоне==
	`docker compose up -d --build`

	==Посмотреть статус всех сервисов==
	`docker compose ps`

	==Читать логи всех контейнеров в реальном времени==
	`docker compose logs -f`

	==Логи конкретного сервиса (например веб-приложения)==
	`docker compose logs -f web`

	==Остановить контейнеры (данные в томах сохраняются)==
	`docker compose down`

	==Полное удаление стека вместе с дисковыми томами (сброс счетчиков)==
	`docker compose down -v`
